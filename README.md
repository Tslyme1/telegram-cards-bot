# telegram-cards-bot

Простой Telegram-бот для группового чата: участники выдают друг другу
жёлтые карточки, за 6 жёлтых выдаётся красная, и участник с красной
карточкой мутится в чате на 30 секунд.

## Команды

- `/card` — выдать жёлтую карточку. Работает тремя способами:
  - **в чате ответом** на сообщение участника: `/card` или `/card причина`;
  - **в чате без ответа**: `/card` или `/card причина` — бот покажет список
    участников кнопками (кнопки действуют только для того, кто вызвал команду);
  - **в личке с ботом**: `/card` — выбрать чат, затем участника, затем
    отправить причину сообщением или нажать «Без причины».

  Результат бот в любом случае публикует в самом чате — кому, от кого и за что.
  Раздавать карточки можно не чаще раза в 10 секунд (с одного аккаунта).
  На 6-й жёлтой карточке подряд участник получает красную, счётчик жёлтых
  сбрасывается, и бот пытается заглушить участника в чате на 30 секунд.
- `/list` — список участников чата с количеством жёлтых и красных карточек
  (работает и в чате, и в личке).
- `/start`, `/help` — краткая справка.

Прежние названия `/yellow`, `/cards` и `/kabany` продолжают работать как
псевдонимы.
Список команд в меню Telegram настраивается отдельно, через
[@BotFather](https://t.me/BotFather) (`/setcommands`) — он влияет только на
подсказки, а не на то, какие команды понимает бот.

## Что нужно настроить у бота

1. В чат бота **обязательно** добавить администратором с правом
   «Ограничивать участников» (Restrict members) — без этого мут на красной
   карточке не сработает; выдача карточек и список работают без него.
2. В [@BotFather](https://t.me/BotFather) **отключить privacy mode**:
   `/setprivacy` → выбрать бота → `Disable`.

## Откуда берётся список участников

Bot API **не позволяет боту получить полный список участников группы** —
такого метода просто нет, это ограничение Telegram, а не бота. Поэтому список
для выбора бот собирает сам из всех доступных источников:

- участники, которые пишут в чате (нужен выключенный privacy mode);
- вступившие в чат при боте;
- любые изменения состава через обновления `chat_member` — это ловит и тех,
  кто вступил молча и ничего не писал (нужны права администратора у бота и
  подписка на этот тип обновлений, см. ниже);
- упоминания вида «текстовая ссылка на пользователя» в сообщениях;
- администраторы чата — подтягиваются автоматически при каждом показе списка.

Чтобы приходили обновления `chat_member`, при регистрации webhook нужно явно
подписаться на них — Telegram не шлёт их по умолчанию:

```bash
curl -F "url=https://your-project.vercel.app/" \
     -F 'allowed_updates=["message","callback_query","chat_member","my_chat_member"]' \
     https://api.telegram.org/bot<BOT_TOKEN>/setWebhook
```

Выдача карточки ответом на сообщение работает независимо от всего этого —
получатель берётся прямо из сообщения. Себе и ботам карточки не выдаются.

Есть два независимых способа запуска — выберите один.

## Способ 1: свой сервер / компьютер (long polling)

Бот сам опрашивает Telegram, отдельный публичный URL не нужен. Данные
хранятся в SQLite-файле.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-local.txt

export BOT_TOKEN=123456:your-telegram-bot-token
python bot.py
```

Процесс должен работать постоянно (например, на VPS через `systemd`/`screen`,
или на Railway/Render как worker) — пока он не запущен, бот не отвечает.
Счётчики карточек хранятся в `cards.db` (путь переопределяется переменной
`DB_PATH`).

## Способ 2: Vercel (webhook)

На Vercel код выполняется как serverless-функция, поэтому long polling не
подходит — вместо этого Telegram сам присылает обновления на HTTPS-эндпоинт
(`api/webhook.py`), а карточки хранятся во внешнем хранилище Vercel KV
(вместо файла, который на Vercel не сохраняется между вызовами).

1. Подключите репозиторий в Vercel (Import Project).
2. В **Storage** создайте базу **KV** и подключите её к проекту — Vercel
   сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
3. В **Settings → Environment Variables** добавьте:
   - `BOT_TOKEN` — токен бота от @BotFather;
   - `WEBHOOK_SECRET` — любая случайная строка (необязательно, но
     рекомендуется — защищает эндпоинт от чужих запросов).
4. Задеплойте проект и скопируйте домен, например
   `https://your-project.vercel.app`.
5. Зарегистрируйте webhook у Telegram (один раз, из терминала):

   ```bash
   curl -F "url=https://your-project.vercel.app/api/webhook" \
        -F "secret_token=<значение WEBHOOK_SECRET, если задали>" \
        https://api.telegram.org/bot<BOT_TOKEN>/setWebhook
   ```

6. Добавьте бота в нужный чат администратором (см. выше про право
   «Ограничивать участников»).

Проверить, что webhook встал: `https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo`.

## Структура проекта

- `bot.py`, `storage.py`, `requirements-local.txt` — способ 1 (long polling +
  SQLite). Внимание: здесь остался прежний способ выдачи — командой
  `/yellow [причина]` ответом на сообщение прямо в чате, без диалога в личке.
- `api/webhook.py`, `storage_kv.py`, `kv.py`, `telegram_api.py`,
  `pyproject.toml` — способ 2 (Vercel webhook + Vercel KV). `pyproject.toml`
  задаёт и точку входа для Vercel (`api/webhook.py`, переменная `app`), и
  зависимости именно этой функции (Flask, requests) — чтобы Vercel не тянул
  тяжёлый `python-telegram-bot`, который нужен только способу 1.
- `config.py` — общие настройки (порог карточек, кулдаун, длительность мута).
